# World Data Explorer

Interactive world atlas that visualizes **30 economic, demographic, social and geopolitical indicators** on a WebGL map — with layer blending, historical time travel and hand-curated diplomacy data.

**Live demo → https://grand-world-data-explorer.vercel.app/**

## Features

- 🗺️ **30 map layers** in 6 groups (Demographics, Economy, Social, Governance, Diplomacy, Map Style), colored per country by real data
- 🎚️ **Combine mode** — blend any set of indicators into a single composite score, normalized per layer (percentile clipping + log/linear scaling)
- ⏳ **Historical layers with time slider** — scrub or play through centuries of population, life expectancy and GDP per capita (Our World in Data / Maddison Project)
- 💬 **Hover tooltips with the math shown** — each value explains how it was computed, including the per-layer normalization breakdown in combine mode
- 🌍 **Country sidebar** with 7 tabs: Economy, Government, Diplomacy, Military, Cultures, Religion, History
- ⚔️ **Diplomatic relations on the map** — wars, conflicts, rivalries and alliances drawn from a hand-researched dataset (Supabase)
- 🚢 **Trade routes layer** — great-circle export/import arcs per country (CIA World Factbook)
- 📱 **Responsive layout** — usable on phones; the country panel is capped to the top half of the screen so the map stays visible
- ⚡ Per-indicator caching, debounced layer loading, GPU-evaluated color expressions

## Architecture

Single-page app with **no server of its own**: Supabase (PostgreSQL) is used as a **backend as a service**. The browser queries it directly with the public anon key, protected by read-only Row Level Security policies. It holds two kinds of data:

- **Relational tables** (`governments`, `ministers`, `relationships`, `country_codes`) with the hand-curated government and diplomacy data. Schema in [`csv-data/create_tables.sql`](csv-data/create_tables.sql).
- **A `datasets` table** (`key` → `jsonb`) with a snapshot of every other dataset the map shows (World Bank, IMF, static JSON, historical series). Schema in [`supabase/datasets_table.sql`](supabase/datasets_table.sql).

A scheduled GitHub Action runs [`scripts/refresh-datasets.mjs`](scripts/refresh-datasets.mjs) twice a week to refresh those snapshots from the public APIs, using a service role key that never reaches the browser.

- **Data access layer** ([`src/lib/datasets.js`](src/lib/datasets.js)): every dataset is resolved as in-memory cache → Supabase snapshot → the original source (live World Bank/IMF API or self-hosted JSON). The app keeps working, just slower, if a snapshot is missing.
- **Config-driven layers**: every layer is a declarative entry in [`src/layers.js`](src/layers.js) (source, indicator, unit, scale, format). Data hooks dispatch on the `source` field — adding a World Bank layer is one config object, zero new logic.
- **One MapLibre expression**: each layer resolves to a single `['match', …]` fill expression evaluated on the GPU; hover/selection use imperative `setFeatureState`, so the map never re-renders through React.
- **Reproducible data pipeline**: curated datasets in `public/data/` are generated by the scripts in [`scripts/`](scripts/) (`npm run fetch-data`, `npm run fetch-historical`) and pushed to Supabase with `npm run refresh-datasets`.
- **State**: a single Zustand store ([`src/store/useStore.js`](src/store/useStore.js)) for layers, selection, caches and UI state.

More detail in [`docs/architecture.md`](docs/architecture.md).

## Running locally

```bash
git clone https://github.com/GabrielLacrampe/world-data-explorer.git
cd world-data-explorer
npm install
npm run dev
```

The app reads from Supabase, so you need your own project. Create the tables by running [`supabase/datasets_table.sql`](supabase/datasets_table.sql) and [`csv-data/create_tables.sql`](csv-data/create_tables.sql) in the SQL editor, then add a `.env` with:

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

To fill the `datasets` table, add `SUPABASE_SERVICE_ROLE_KEY` to the `.env` and run `npm run refresh-datasets`. To regenerate the static files in `public/data/`: `npm run fetch-data` / `npm run fetch-historical`. Tests: `npm test`.
